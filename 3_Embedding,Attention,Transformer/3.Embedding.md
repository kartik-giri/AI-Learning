# Embedding:

# Why we need embedding?
- As we when user prompts the LLM.
- That text is tokenized in to smaller unit called tokens.
- The LLM tokenizer breaks the text in to multiple smaller units called tokens.
- And than assigns the token ID to each token using tokenizer voalbulory. Every tokenizer vocabolary have the token ID for common tokens.
- The token ID is numerical number it is just used to identify the token.

- Input text

"I love AI"

Tokenization

["I", " love", " AI"]

Token IDs

[40, 982, 1256]

- Does it means we can give these token IDs to a transformer and expect it to understand the meaning and relationship between?
- No that's why we need embedding.
- The LLM models can learn and relationship between these vectors during training.
- Similarity is not guaranteed just because two words seem related to humans. It is learned from training data, and the representation depends on context and the model.


# What is Embedding?
- Embedding is the process of representing tokens or other information in to the high dimensional vectors which is ordered list of numerical values.
- And it captures the semantic relaitonships and meaning and allows the model to compare and process them efficinently.
- For example 
- LLM converts each token ID in to vectors with thousand of dimensions.
- Embedding is the way of representing tokens numerically so that neural network can learn and use the relationship between different pieces of information.
- Like emmbeddings of Apple, Banana, Orange will have less distance among which means they are related to each other.
- There are embedding distance is closer because they have similar features which aredimensions in vectors.

# How are embeddings created?
- Here's the simplified process:
1. Token ID
   982

2. Embedding lookup table
   Find the vector associated with ID 982. The embedding layer converts each token ID into its own vector.

3. Embedding vector
   [0.23, -0.81, 0.45, 0.67, ...]

4. Transformer layers

- Token ID identifies a token. Embedding represents that token numerically in a learned vector space.

# Embedding in RAG
- Retrieval -> It retrieves the relevant information from the your data.
- Augmented -> Add the information into users prompt.
- Generation -> Let the LLM generate the anser using that context.

- Embedding is used in RAG while uploading documents and when Users asks a quesiton.

- Uploading documents- All this is done offline.
1. Upload doc.
2. Server read the content of doc.
3. Split long document in to smaller pieces called chunks.
4. COnverts each chunk in to vector using embedding model.
5. Vector db Store vectors + original text + metadata.
- Vector	        Original text	            Metadata
[0.12, 0.85, ...]	Inkflow uses WebSockets...	document: architecture.md

- User asks a question:
1. User Question : How does Inkflow broadcast drawing events?

2. Embedding model: Tokenize the question and converts it into single final  vector.

3. Vector database search: Find stored vectors that are semantically similar. 
- This is called similarity search or vector search.
- Common ways to measure vector similarity include:
- Cosine similarity - differnce between two vectors.

4. Retrieve relevant chunks : DB returns matches vectors original text and metadata.

5. Build augmented prompt: Server combine the question with retrieved context.

6. LLM generates answer: Let LLM generate the answer using given context.

7. Return answer to user.


- Component	Responsibility
- Embedding model	Converts text into vectors
- Vector database	Stores vectors and searches for similar vectors
- LLM	Reads the retrieved context and generates an answer
- Backend	Coordinates the entire RAG workflow

1. Semantic search is what you're trying to achieve: finding information based on meaning and intent rather than just matching exact keywords.

2. Vector search is one technique used to achieve semantic search: comparing numerical vectors to find similar representations.

# LLMs use token-level vector representations to understand and generate language. RAG uses chunk-level embeddings to retrieve relevant knowledge.
